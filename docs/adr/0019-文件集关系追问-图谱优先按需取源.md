# 文件集关系追问:用户选文件集,图谱优先,源码按需取源

追问器新增一种上下文范围:用户显式选择 2-N 个文件,围绕这些文件的职责、调用、依赖与关系发问。v1 强依赖 `.understand-anything/knowledge-graph.json`:基础上下文由选中文件的 file/class/function 摘要、选中文件之间的 edges、以及选中文件指向外部的边界关系组成;源码只在二段式规划中由模型点名少数 graph 节点后按 `lineRange` 临时切片补入,不整文件塞入 prompt。

## Considered Options

- **全项目追问**:覆盖面大,但默认上下文过宽,关系问题容易噪声过多。否决;后续可作为文件集为空时的独立模式。
- **打开的 tabs 即文件集**:实现轻,但阅读动作不等于关系分析选择。否决。
- **无图谱时硬塞源码 fallback**:看似可用,但成本高且关系判断无确定锚点。否决;v1 无图谱时明确提示先生成图谱。
- **整文件源码拼接**:简单直接,但几个文件稍大就超窗且信噪比差。选图谱摘要/关系为主,源码仅按需切少数节点。

## Consequences

- 文件树需要可开关的选择控件;关闭只隐藏控件,不清空已选文件,清空由追问器单独动作完成。
- 追问器需要范围切换:当前文件 / 已选文件(N)。当前文件继续走既有 `/api/query`;已选文件走新的多文件关系查询链路。
- 后端需要多文件关系上下文装配:只接受 graph 中存在的选中文件;无图谱或选集无可用 graph 节点时返回明确错误。
- 二段式按需取源复用 ADR-0017 的规划形态,但 fetchable 来自选中文件内的 graph class/function 节点;切源仍是确定性 `reader.read_file + lineRange`。
- 文件集关系追问不激活目标文件,不触发幽灵注释生成,不写目标文件旁路缓存,守零字节污染与真空态。
