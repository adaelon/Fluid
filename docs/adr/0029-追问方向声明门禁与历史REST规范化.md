# 追问方向声明门禁与历史 REST 规范化

### §0029 追问完成契约

**决策**:方向声明须在首个回答 delta 前对齐 QueryMap;历史 REST 的空 `sources` 恒为 `[]`。

**否决**:
- 只加强 Prompt:模型仍可误选空图分支,错误回答仍可能成为完整轮次。
- 完整首答流完后再纠正:用户已看到错误文本,还需新增撤回/替换协议。
- 只在消费点散落 `sources ?? []`:REST 与内部类型继续失配,新消费点仍会崩溃。

**命门**:方向首行由后端从同一 QueryMap 派生并校验;首次违约只在原 Prompt/map/evidence 边界内纠正一次,终验失败无 `done`、无持久轮次;旧记录可省略 `sources`,对外与前端内部一律归一为空数组。
**何时回头**:回答改为后端结构化渲染,或追问协议引入可原子替换整篇回答的帧时。
