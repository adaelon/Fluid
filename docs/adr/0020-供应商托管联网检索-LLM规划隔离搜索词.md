# 供应商托管联网检索:LLM 规划隔离搜索词

选区解释与追问器共用当前 LLM 配置的供应商托管 Web Search。一次联网作答拆成三次模型调用:先由不开启联网工具的 LLM 阅读代码语境并生成「公开检索请求」,再只用该请求执行托管检索,最后把联网检索结果与代码上下文合并生成解释。系统不把原始源码直接附加到搜索请求,但 v1 不预览检索词、也不做语义级隐私校验;供应商未返回 URL 时允许交付,但必须标记为「联网无来源」。

## Considered Options

- **确定性或候选约束解析**:能减少幻觉,但须先新增多语言 import、manifest 与符号归一化能力。否决进入 v1,后续可增强。
- **源码上下文与 Web Search 一次请求**:调用更少、延迟更低,但无法保证供应商不会用私有源码生成搜索词。否决。
- **Fluid 自建搜索与开页网关**:来源更可审计、供应商更中立,但 v1 须承担 SSRF、重定向、内容清洗与 Prompt Injection 防护。否决。

## Consequences

- 一次联网解释包含「LLM 规划 + 托管检索 + LLM 作答」三次模型调用,以额外延迟与 Token 成本换取搜索词隔离。
- v1 的包名、版本与符号路径归一化依赖 LLM,可能产生错误或过宽的公开检索请求。
- 检索词生成后直接联网,不逐次征求用户确认;Prompt 约束只能降低、不能消除私有标识符被模型带入检索词的风险,用户已接受此 v1 风险。
- `LlmProxy` 仍是唯一出网组件,但须扩展供应商托管搜索能力;当前供应商不支持时降级为普通解释并明确提示。
- 规划失败、不支持 Web Search、超时或限流均不阻断作答:使用本地上下文继续生成,显式标记「未核验:联网失败」并允许重新生成,不得静默伪装成联网成功。
- 联网缓存身份包含供应商、模型与搜索模式;用户可以关闭联网或主动重新生成。
- 本机第三方源码定位不进入 v1,后续可作为独立增强补充。
