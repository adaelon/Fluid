## 1. 拓扑与技术栈

```
$ npx fluid ./project
┌─────────────────── 浏览器前端 (CodeMirror 6) ───────────────────┐
│ FileTree(L0) · CodeView/CodeEvidencePeek · tree-sitter WASM 解析 │
│ GhostStore(内存) · GenerationScheduler · QueryPanel/Presentation/Layout │
└───────────────▲───────────────────────────── WS/HTTP ──────────┘
                │ source / skeleton / 流式生成 / 追问
┌───────────────┴──────────── 本地后端 (Rust) ────────────────────┐
│  ProjectReader(fs) · GraphCatalog(.ua + legacy,多作用域可选)     │
│  OrientationProtocol(类型/校验/hash) · ContextAssembler          │
│  WebEvidenceService(共享证据编排)                                │
│  LLMProxy(持 key、唯一出网边界)                                  │
│  CacheStore(.fluid/capsules|selections|orientations)             │
│  QueryThreadStore(.fluid/query-threads/v1,项目级持久记录)          │
└──────────────────────────────────────────────────────────────────┘
        出网边界:仅 LLMProxy 出网;解析/骨架/缓存命中全本地
```

- **前端**:渲染 + 解析 + 调度 + 内存态幽灵注释。无 key、不落盘。
- **后端**:文件 IO、图谱加载、上下文装配、LLM 代理、`.fluid/` 缓存与项目级追问记录。
- **后端技术栈**:Rust + `axum`/`tokio`(HTTP/WS)、`serde_json`、`encoding_rs`(非 UTF-8 兜底解码;图谱实测为合法 UTF-8)、`reqwest`(LLM 流式代理)、`ts-rs`(类型生成 TS)。分发:各平台预编译 binary(`fluid ./project`),非 npx。
- **前端技术栈**:Vue 3(SFC)、TypeScript、CodeMirror 6、tree-sitter WASM、Vite。CM6 实例与 GhostStore 等命令式大对象用 `shallowRef`/`markRaw` 持有,不进 Vue 响应式(ADR-0014)。
- 依据:ADR-0009(浏览器解析)、ADR-0010(拓扑)、ADR-0012(CM6)、ADR-0013(后端 Rust)、ADR-0014(前端 Vue 3)。

## 3. 核心数据类型

```typescript
// L0 骨架
type FileNode   = { path: string; name: string; lang: 'py' | 'rs' | 'other' };
type Edge       = { source: string; target: string; type: 'calls'|'imports'|...; };
type GraphNode  = { id: string; type: 'file'|'class'|'function'|'document';
                    filePath: string; summary: string; lineRange?: [number, number] };
type GraphOrigin = '.ua' | '.understand-anything';
type GraphSnapshot = { identity: string; origin: GraphOrigin; scopeRoot: string;
                       path: string; contentHash: string; graph: KnowledgeGraph };
type GraphCatalog = { projectRoot: string; snapshots: GraphSnapshot[] };

// 文件定向协议(S-ORI-1;完整冻结结构见切片方案 §1)
type CodeEvidenceRef = { id: string; filePath: string; startLine: number;
                         endLine: number; symbol?: string };
type OrientationActor = { id: string; name: string; role: string;
                          boundary: 'inside-file'|'project'|'external' };
type OrientationType = { name: string; ownerActorId: string; meaning: string };
type OrientationFlowStep = { fromActorId: string; via: string; payload: string;
                             toActorId: string; why: string; evidenceIds: string[] };
type OrientationFlow = { id: string; name: string;
                         kind: 'request'|'response'|'control'|'stats'|'other';
                         why: string; steps: OrientationFlowStep[] };
type FunctionRole = { fnId: string; lane: 'core'|'supporting'; flowIds: string[];
                      stage: string; receivesFromActorIds: string[];
                      consumes: string[]; sendsToActorIds: string[];
                      produces: string[]; why: string; evidenceIds: string[] };
type SupportingCapability = { name: string; why: string;
                              functionIds: string[]; evidenceIds: string[] };
type OrientationWalkthrough = { title: string; input: string;
                                steps: { text: string; evidenceIds: string[] }[] };
type OrientationInvariant = { text: string; evidenceIds: string[] };
type FileOrientationCard = { schemaVersion: number; orientationId: string;
                             filePath: string; purpose: string;
                             actors: OrientationActor[]; types: OrientationType[];
                             coreFlows: OrientationFlow[];
                             supportingCapabilities: SupportingCapability[];
                             functionRoles: FunctionRole[];
                             walkthrough: OrientationWalkthrough;
                             invariants: OrientationInvariant[];
                             evidence: CodeEvidenceRef[];
                             coverage: { mode: 'full-source'|'bounded-source';
                                         omittedFunctionIds: string[] } };

// ORI3 后端内部边界(S-ORI3-1~ACC;生产与验收已收口)
type FunctionRoleDraft = Omit<FunctionRole, 'evidenceIds'>;
type SupportingCapabilityDraft = Omit<SupportingCapability, 'evidenceIds'>;
type OrientationRoleBatchDraft = { functionRoles: FunctionRoleDraft[];
                                   supportingCapabilities: SupportingCapabilityDraft[] };
type OrientationFunctionEvidenceSource = { fnId: string;
    kind: 'exact'|'signature-only'; lineRange: [number, number]; symbol: string };
type OrientationFunctionEvidenceBindings = { byFnId: Map<string, string>;
                                              evidence: CodeEvidenceRef[] };

// 文件定向前端帧与激活闸门(S-ORI-4)
type OrientationFrame =
  | { kind: 'cache-hit'; reqId: string }
  | { kind: 'status'; reqId: string; phase: 'planning-source'|'orienting';
      message: string }
  | { kind: 'card'; reqId: string; card: FileOrientationCard }
  | { kind: 'done'; reqId: string }
  | { kind: 'error'; reqId: string; message: string };
type OrientationViewState = { mode: 'idle'|'loading'|'ready'|'error';
                              reqId?: string; filePath: string;
                              phase?: 'connecting'|'planning-source'|'orienting';
                              cacheHit: boolean; card?: FileOrientationCard;
                              errorMessage: string };

// 大文件定向的后端内部取源结果(S-ORI-3)
type OrientationSourceChunk = { fnId: string; numberedSource: string };
type OrientationSourceSelection = { sources: OrientationSourceChunk[];
                                    omittedFunctionIds: string[] };

// 追问相关源码的后端内部候选与请求内证据目录(S-QSRC-1)
type QuerySourceTarget = { id: string; graphId?: string; filePath: string;
                           lineRange: [number, number]; symbol?: string;
                           hint: string }; // hint 只导航,不进入证据
type CodeEvidenceRef = { id: `E${number}`; filePath: string;
                         startLine: number; endLine: number; symbol?: string };
type EvidenceCatalog = { entries: Array<{ reference: CodeEvidenceRef;
                                          exactSource: string }> };
type QueryMap = { actors: OrientationActor[];
                  direction: OrientationFlowStep[]; // 仅保留异 actor 且有本次 E# 的步骤
                  coreFunctionIds: string[];
                  supportingFunctionIds: string[];
                  walkthrough: OrientationWalkthrough;
                  evidence: CodeEvidenceRef[] };     // 与同请求 EvidenceCatalog 同 ID/锚点

// tree-sitter 解析产物(前端)
type FunctionSpan = { id: string; name: string; lineRange: [number, number] };
type FileParse    = { roster: FunctionSpan[]; keyLines: Map<fnId, number[]> };

// 生成产物(幽灵注释)
type Capsule        = { fnId: string; signature: string; summary: string;
                        complexity: string; io: string; orientationId: string;
                        role: FunctionRole };
type LineAnnotation = { fnId: string; lineNumber: number; text: string; color: string };

// 供应商托管联网检索(S-WEB-1/S-WEB-2)
type SourceLink      = { title: string; url: string };
type WebSearchResult = { text: string; sources: SourceLink[] }; // sources 可为空
type SearchPlan       = { action: 'local' } | { action: 'search'; query: string };
type EvidenceStatus   = 'project-source' | 'web-cited' | 'web-uncited' | 'unverified';
type EvidenceOutcome  = { status: EvidenceStatus; text?: string;
                          sources: SourceLink[]; warning?: string };

// 代码选区解释(S-SEL-1)
type SelectionKind = '模块' | '类型' | '函数' | '方法' | '变量' | '表达式' | '未知';
type SelectionExplanation = { selectedText: string; kind: SelectionKind;
                              meaning: string; roleHere: string; origin?: string;
                              evidenceStatus: EvidenceStatus;
                              sources?: SourceLink[]; warning?: string };

// 追问流式帧(S-QWEB-1/S-QWIRE-1;done 确认已落盘轮次)
type QueryFrame =
  | { kind: 'status'; phase: 'planning-source'|'planning-web'|'searching-web'|
                            'answering'|'fallback';
      message: string }
  | { kind: 'map'; map: QueryMap }
  | { kind: 'evidence'; status: EvidenceStatus;
      sources?: SourceLink[]; warning?: string }
  | { kind: 'delta'; text: string }
  | { kind: 'done'; threadId: string; updatedAt: string }
  | { kind: 'error'; message: string };

// 当前范围内的有界追问轨迹(S-QTRACE-1;由完整持久线程派生,不在 wire 上传)
type QueryTurn = { question: string; answer: string; codeEvidenceIds: string[] };
type QueryTrace = { scopeKey: string; scopeRevision: string;
                    originalQuestion: string; turns: QueryTurn[] };

// 项目级完整追问记录(S-QTHREAD-1/S-QAPI-1/S-QWIRE-1;REST/WS 共用)
type QueryScopeSpec =
  | { kind: 'current'; paths: [string] }
  | { kind: 'selected'; paths: [string, string, ...string[]] };
type PersistedQueryTurn = { question: string; answer: string; map: QueryMap;
                            evidence: QueryViewState['evidence'] | null;
                            codeEvidenceIds: string[]; completedAt: string };
type QueryThread = { schemaVersion: 1; id: string; title: string;
                     createdAt: string; updatedAt: string; scope: QueryScopeSpec;
                     sourceRevision: string; originalQuestion: string;
                     turns: PersistedQueryTurn[] };
type QueryThreadFreshness = { freshness: 'fresh'|'stale';
                              staleReason?: 'source-changed'|'source-missing' };
type QueryThreadSummary = { id: string; title: string; updatedAt: string;
```

## 6. 缓存键(对 ADR-0003 的细化)

- **函数胶囊**:键 = `stableHash(函数源码 span + orientationContextHash + providerBaseUrl + model + CAPSULE_PROMPT_VERSION + CAPSULE_SCHEMA_VERSION)`;旧 schema 自然 miss。卡片因无关源码变化换 `orientationId` 但规范化坐标未变时,未改兄弟函数仍命中并由后端重绑定当前 ID;角色/flow/evidence 任一坐标变化则 miss。
- **收益**:文件内某函数改动只失效该函数,其余函数缓存仍命中,重算最小化。
- **行级注释**随所属函数胶囊一同存取(同一缓存条目)。
- **选区解释**:键 = `hash(整文件源码 + UTF-8 byte range + providerBaseUrl + model + promptVersion + webMode)`;`forceRefresh` 跳过读并覆盖同一键。
- **文件定向卡**:键 = `stableHash(整文件源码 + relevantGraphSetHash|no-graph + providerBaseUrl + model + ORIENTATION_PROMPT_VERSION + ORIENTATION_SCHEMA_VERSION)`;读写两端都以当前源码/文件路径/roster 重新校验,`bounded-source` 卡还会按后端注入的 omitted 补集重建可用 span 并拒绝越界 evidence,坏卡视为 miss;`S-ORI3-3` 将 prompt version 提升为 `orientation-p5`,旧阶段 B 所有权契约缓存自然 miss;`S-ORI3-ACC` 复验所有身份字段 miss、坏卡拒绝与源码 bytes/mtime 不变。
- **定向上下文 hash**:`stableHash(normalized actors + types + flows + functionRoles + evidence)`;集合型字段排序去重,核心流 step 顺序保留,供后续胶囊键只随真实坐标变化而失效。
- **选区缓存门**:`project-source`/`web-cited`/`web-uncited` 与无 warning 的稳定本地结果可缓存;规划、协议、限流、超时等可见降级不缓存。
- **存储**:函数/行/翻译在 `.fluid/capsules/<key>.json`,选区解释在 `.fluid/selections/<key>.json`,文件定向卡在 `.fluid/orientations/<key>.json`;源码零字节不动(核心律 1)。
- **追问记录不是缓存**:`QueryThreadStore` 独立写入 `.fluid/query-threads/v1/<thread-id>.json`;同目录临时文件 + replace/rename 提交完整记录,不随模型、Prompt 或缓存 schema 失效而删除。
- > 说明:此处把 ADR-0003 的"文件内容 hash"细化为"函数 span hash",以支持部分失效;语义一致,粒度更细。

## 7. 前端激活状态机

```
VACUUM ──open file──> LOADING ──source+skeleton 到达──> PARSING(tree-sitter)
PARSING ──roster+keyLines──> ORIENTING(connecting/cache lookup/planning/orienting)
  ORIENTING:status → 显示 pending;card → 立即渲染文件定向卡,函数闸门仍关闭
  ORIENTING ──同 reqId、同文件 card+done──> ACTIVATING_CAPSULES
  ACTIVATING_CAPSULES:nextTick 确认卡片已呈现
                      → 标记函数占位
                      → scheduler 按视口邻近全量排队并有限并发发 /api/generate
                        (每请求带 ready card 的 orientationId + 完整 rosterSpans)
                      → 后端重算定向身份、读取自有缓存卡并绑定精确 FunctionRole
                      → 每函数:capsule 到渲 lane/stage/具名方向/可展开依据;line 到渲行级 widget
  ORIENTING ──error/连接提前关闭──> ORIENTATION_ERROR ──retry──> ORIENTING
ACTIVATED ⇄ scroll:只重排尚未发出的全文件队列,不改变激活单元
GENERATING ──暂停生成──> PAUSED(关闭全部 worker WS;pending→paused;settled/error 与滚动位置不变)
PAUSED ──继续生成──> GENERATING(只把 paused 函数按当前视口距离重新排队)
  后端在供应商 IO 期间并行监听 WS;peer close 立即丢弃该函数 future,不产生迟到缓存
ACTIVATED ──fold/unfold──> 纯 UI 显隐,GhostStore 不变,零重算
任意激活态 ──switch/close──> VACUUM(取消定向 socket + scheduler;释放 GhostStore;.fluid/ 缓存留存)
旧帧 ──reqId/文件路径/激活代次任一不匹配──> 丢弃
```

Markdown 文档仍直接进入文档渲染视图,不解析、不请求 `/api/orient`、不启动函数调度,保持真空态。

代码选区临时状态机独立于文件激活与 GhostStore:

```text
IDLE ──单一非空单行选区──> ACTION(锚定「解释」)
ACTION ──click──> CONNECTING ──status──> RESOLVING/PLANNING/SEARCHING/ANSWERING/FALLBACK
RESOLVING/... ──result──> RESULT(固定结构 + 证据状态 + 可选来源)
RESULT ──重新生成──> CONNECTING(forceRefresh=true)
任意临时态 ──Esc/外点/选区变化/切文件──> IDLE(取消 socket + 递增请求序号)
旧帧 ──reqId 或请求序号不匹配──> 丢弃
```

追问器状态投影独立于答案 Markdown 渲染:

```text
IDLE ──首问(current|selected, allowWeb)──> TRACE(originalQuestion, turns=[])+CONNECTING(reqId)
DONE ──后续问题──> CONNECTING(新 reqId,重放同 scope/revision 的 trace)
CONNECTING ──status*──> SOURCE_PLANNING/PLANNING/SEARCHING/ANSWERING/FALLBACK
状态态 ──map──> MAP_READY(先渲方向、核心/外围、walkthrough 与可点击 E#)
MAP_READY ──evidence?──> 保留网页证据元数据
MAP_READY ──delta──> 累加纯文本 answer;map 恒保留
流式态 ──done──> TRACE.turns += 完整(question,answer,已知 E#)+DONE(每个 turn 保留各自 map 并渲染 Markdown/LaTeX)
流式态 ──error──> ERROR(错误追加显示;已收 answer/evidence 不清空,partial 不入 trace)
reqId 不匹配或请求代次陈旧 ──> 原状态(帧丢弃)
map 前 evidence/delta/done、map 后 status/重复 map、delta 后 evidence/重复 evidence ──> ERROR(可见协议错误,取消 socket)
回答中的未知 [E#] ──> 保留纯文本 + 可见告警,不生成源码跳转
切 scope/文件/revision ──> 取消 socket;若已选持久线程则保留完整阅读投影,仅匹配 fresh 范围可续问
点击“新追问”或关闭 ──> IDLE(清当前线程投影,项目历史摘要保留)
```

项目历史加载与线程切换独立受项目代次保护:

```text
APP_START ──list──> HISTORY(newest-first summaries + isolated warnings)

旧 list/get/WS 结果 ──generation/sequence/threadId 不匹配──> 丢弃
```

追问呈现状态不进入 `QueryTrace`,也不改变请求生命周期；所有入口归约同一个纯 layout reducer:

sidebar 复用既有持久宽度并以“项目历史列表 -> 线程详情”两级视图避免横向堆叠；dock/focus 才显示单一 toolbar 历史选择器。focus wrapper 的层级低于设置模态与命令面板;背景 IDE DOM 保持挂载但不可交互。每个 completed turn 用同索引快照保存 map/evidence/安全 HTML,切轮后 Markdown/KaTeX 只处理当前挂载答案;方向图与证据折叠容器以 turn index 隔离,不继承上一轮展开态。宽视口显示独立历史栏,窄于 1280px 时降为顶部选择器。Code Peek 直接 `fetchFile(reference.filePath)`,不会调用 `App.open()`、修改 tabs/`activePath` 或加入 Editor 生成链路。

`S-QHISTORY-1/S-QSTALE-1/S-QLEFT-1` 后,上述运行态与项目历史投影均由 `App` 创建的单一 `QueryWorkspaceController` 持有;`QueryPanel` 壳层只调用 controller 的 list/select/delete/create/fork 动作。关闭或收起只隐藏呈现，显式“新追问”才清当前阅读投影；文件、scope 或 revision 变化取消在途请求并保留完整持久线程供阅读。stale 投影不生成可点击答案 E#,`QueryMapView` 同时禁用方向图证据按钮,但网页来源链接不进入该闸门;fork 结果还要在前端复验新 ID、fresh、零 turns、新 revision、同范围与同原始问题。`App.doSwitch` 在后端换根前先递增项目代次并取消旧请求,成功后加载新根摘要;旧 list/get/fork/WS 均不能写入新项目。

## 8. 追问上下文装配(分层,ADR-0006)

```
buildQueryEvidence(scope, question, trace, orientation, focus):
    require QueryContext.filePath == active file
    currentRevision = ready FileOrientationCard.orientationId
    trace = QueryThread.toQueryTrace(currentRevision | canonicalSelectedSet)
    history = keep(originalQuestion) + newestCompleteTurns(trace, charBudget=8_000)
    if older turns omitted: history += explicit omission marker
    snapshots = GraphCatalog.resolveEach(scope.files)          # 每个文件独立解析最近祖先作用域
    navigation = file/capsule summaries + real in-graph edges + history + question
    mandatory = currentSmallFullSource | explicitFocus | currentLargeOrientationCore
    candidates = backendSpansQualifiedByGraphIdentity(snapshots)
    need = candidates.empty ? [] : oneRoundSourcePlan(navigation, mandatory, candidates)
    reread source files; refresh graph ownership and current orientation
    selected = exactCandidateIds(need) |> uniqueExactSpanRebase
    catalog = assembleContiguousEIds(mandatory + selected, sharedBudget=12_000)
    assert every catalog entry byteEquals backSlice(currentSources)
    queryMap = current ? rebindOrientationToCatalog(orientation, catalog)
                       : minimalSelectedMap(files, question, catalog)
    assert every map actor/evidence ref resolves
    local = navigation + queryMap + catalog                   # summary/历史永不冒充源码证据
    evidence = resolveWebEvidence(proxySnapshot, local, manifests,
                                  None, allowWeb)              # 本地规划完成后再联网
    return { queryMap, prompt: local + untrustedBlock(evidence.text) }
```

文件集追问先逐文件解析所属 `GraphSnapshot`,节点 ID 带 graph identity 隔离;只合并各快照内与选中文件相关的真实节点/边,不合成跨图关系。图谱节点 `filePath` 恒以其 `scopeRoot` 为基准,读取源码前再转换为项目根相对路径。

`S-QTHREAD-1/S-QAPI-1/S-QWIRE-1/S-QHISTORY-1/S-QSTALE-1` 已落下独立 `QueryThreadStore`、真实源码 revision、REST 生命周期、两条 query WebSocket 续问接线、前端项目历史恢复与陈旧版本护栏。前端 controller 首问创建零轮次线程,wire 只发送 `threadId`;后端要求线程 fresh 且 scope/项目匹配,从完整持久记录派生有界 `QueryTrace`,源码规划后继续重读文件、按唯一精确片段重算行号并复验 graph identity。回答流完成后再次核对线程更新时间和源码 revision,原子追加 map/evidence/answer/已知 E# 成功才发送带 `threadId/updatedAt` 的 `done`;controller 据终态更新摘要,选择历史则从 REST 完整 turn 重建阅读投影。源码失配时旧线程只读,`source-changed` 只复制 scope/originalQuestion 到当前 revision 的新线程,不复制旧 turns。LLM、存储、并发线程或源码变化均不追加完整轮次。

前端固定由 `App.allowWeb -> QueryPanel -> streamQuery | streamQueryFiles` 透传同一个布尔值;`App -> createQueryWorkspace -> QueryPanel` 为唯一运行态/历史所有权链。`api.ts` 提供 create/list/get/delete/fork 严格客户端并保留 HTTP status 供 404/409 恢复;传输失败仍归一成 `QueryFrame.error`,再由 `QueryWorkspace.acceptFrame -> reduceQueryFrame` 以同一状态机处理两种 scope。

current map 复用已验证定向卡的 actor/core/supporting/walkthrough,并把卡内证据 ID 按路径与包含行范围重绑定到本请求最具体的 E#;同 actor 局部步骤不伪装成跨组件 direction。selected 没有共享定向卡时只把选中文件作为 actor、真实源码目录作为 walkthrough,direction 明确为空,不把 graph edge 升格为源码事实。前端只把 map.evidence 中存在的 `[E#]` 渲染为跳转;点击后显式打开对应文件并滚到 1-based 起始行。
