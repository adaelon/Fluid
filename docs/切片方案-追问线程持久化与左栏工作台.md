# 追问线程持久化与左栏工作台切片方案

> 状态:实施中（2026-08-10 Grill 完成；`S-QTHREAD-1`、`S-QAPI-1`、`S-QSTATE-R0`、`S-QWIRE-1`、`S-QHISTORY-1` 已完成,下一刀为 `S-QSTALE-1`）。领域术语见 `CONTEXT.md`,关键权衡见 `docs/adr/0028-追问线程项目级持久化与三态呈现.md`。
> 本方案把现有内存追问轨迹扩展为项目级持久化线程,并增加左栏呈现;不改变取源、联网检索、QueryMap、EvidenceCatalog 或答案 Prompt 的语义。

## 目标与边界

**做**:

- 一个项目可以保存多个追问线程;“新追问”创建新线程,不覆盖旧线程。
- 关闭追问器、切换文件、切换范围与重启 Fluid 后,完整问答仍可恢复。
- 同一源码版本的线程可继续追问;源码变更或文件缺失后,旧线程只读并可基于当前源码另建线程。
- 当前文件与已选文件集都绑定真实源码内容版本;文件集路径顺序不同不产生不同身份。
- 追问器由同一状态源投影到左栏、底栏或专注态;位置切换不清历史、输入或在途请求。
- 活动栏可在资源管理器、追问器与收起左栏之间切换;左栏宽度继续复用并持久化现有值。
- 项目历史按最近更新时间倒序展示,标题默认取第一问,并标明追问范围与陈旧状态。
- 支持删除单个线程;删除是显式用户动作,不得因缓存失效或源码变化自动删除。

**不做**:

- 不做跨项目总历史、云同步、导入导出、分享、搜索、改标题、线程分支/合并或跨设备身份。
- 不保存源码字节副本;陈旧线程因此禁止把旧 E# 跳转到当前源码。
- 不恢复进程退出时尚未完成的流式请求;只有完整 `done` 轮次进入可续问轨迹。
- 不把无限历史塞进 Prompt;现有 `QUERY_TRACE_BUDGET_CHARS` 与“原始问题 + 最近完整轮次”裁剪规则不变。
- 不把持久记录放进 `localStorage`,也不把它当作可随模型或 Prompt 版本失效的 `CacheStore` 条目。
- 不支持多个 Fluid 进程同时写同一项目;文件级原子写只防单进程崩溃留下半文件。
- 不在功能刀中顺手调整追问答案样式、取源策略、证据算法或无关 IDE chrome。

## 已确认的现状缺口

- `QueryPanel.vue` 当前拥有 `trace`、呈现快照、输入与 WebSocket;`v-if` 关闭组件会把这些状态全部销毁。
- 文件、范围、选择集或 orientation revision 变化会直接调用 `resetTrace()`,没有可切回的线程集合。
- `QueryTrace` 由前端完整重放,后端没有线程 ID、历史表或持久化写入点。
- current scope 用 `orientationId` 作为 revision;selected scope 只用排序后的路径集,文件内容变化不会改变 revision。
- 历史轮次的 `QueryMap`/证据状态只在前端并行数组中;Markdown HTML 是派生物,不应落盘。
- `CodeEvidenceRef` 只有文件路径与行范围,没有旧源码字节;源码变化后继续跳转会把旧结论错误映射到新代码。
- ActivityBar 的资源管理器按钮永久 active;侧栏只能拖宽,不能收起或切换成追问器。
- `QueryPresentation` 只有 `dock | focus`;现有 ADR-0023 要求切换时保持同一追问状态与在途请求。

## 冻结数据契约

### 1. 持久线程与有界轨迹分离

```typescript
type QueryScopeSpec =
  | { kind: 'current'; paths: [string] }
  | { kind: 'selected'; paths: [string, string, ...string[]] }

interface QueryThread {
  schemaVersion: 1
  id: string
  title: string
  createdAt: string
  updatedAt: string
  scope: QueryScopeSpec
  sourceRevision: string
  originalQuestion: string
  turns: PersistedQueryTurn[]
}

interface PersistedQueryTurn {
  question: string
  answer: string
  map: QueryMap
  evidence: QueryEvidenceState | null
  codeEvidenceIds: string[]
  completedAt: string
}

interface QueryThreadSummary {
  id: string
  title: string
  updatedAt: string
  scope: QueryScopeSpec
  turnCount: number
  freshness: 'fresh' | 'stale'
  staleReason?: 'source-changed' | 'source-missing'
}
```

- `QueryThread` 是完整、持久的用户记录;`QueryTrace` 是从线程派生给模型的有界投影,两者不得再作为同义词。
- 首次提交问题时先创建零轮次线程;首轮失败时保留原始问题供重试,但失败/部分回答不进入 `turns`。
- `done` 前必须先原子写入完整轮次;写入失败则返回可见错误,不能向前端谎报“已保存”。
- `answer`、`QueryMap`、网页证据元数据与已知 E# 落盘;渲染 HTML、CodeMirror 状态、源码字节、API key、Prompt 和流式 delta 不落盘。
- 标题由原始问题第一条非空文本确定,仅在列表呈现时截断;v1 不支持用户改名。

派生规则:

```text
QueryThread(originalQuestion, complete turns)
  -> QueryTrace(scopeKey, currentRuntimeRevision, originalQuestion, complete turns)
  -> render_query_trace(..., QUERY_TRACE_BUDGET_CHARS)
```

Prompt 裁剪只影响本次请求,不得回写或裁剪 `QueryThread.turns`。

### 2. 项目隔离与源码版本

持久目录固定为:

```text
<project>/.fluid/query-threads/v1/<opaque-thread-id>.json
```

- 新增独立 `QueryThreadStore`,随 `ProjectCtx` 一起在 Open Folder 时原子换根;不得复用按模型/Prompt 失效的 `CacheStore`。
- v1 每线程一文件,列表由扫描并校验记录得到,不维护第二份易失配索引。
- 写入使用同目录临时文件 + replace/rename;线程 ID 必须由服务端生成并验证,不能拼接任意用户路径。
- 单个损坏或未知 schema 文件只产生列表告警并被跳过,不得阻断其他线程,也不得静默删除坏文件。
- 删除只允许命中当前项目线程目录内已验证的线程 ID。

源码版本由后端对规范化范围计算:

```text
sourceRevision = SHA-256(
  schema-tag
  + each sorted project-relative path as length-prefixed UTF-8
  + each exact file byte sequence as length-prefixed bytes
)
```

- current scope 只有一个路径;selected scope 先按现有 JS UTF-16 兼容顺序排序并去重,且至少两个路径。
- 任一文件内容、路径或成员集合变化都得到新 revision;mtime、模型、Prompt、图谱与打开顺序不参与。
- 线程 freshness 在读取时以当前项目源码重新计算,不把可变状态永久写死在记录里。
- `fresh` 才能续问;`stale/source-changed` 可阅读或执行“基于当前源码新建追问”;`stale/source-missing` 只能阅读,直到原范围文件重新可用。

### 3. 服务端是持久记录真相源

```http
GET    /api/query-threads
POST   /api/query-threads
GET    /api/query-threads/{threadId}
DELETE /api/query-threads/{threadId}
POST   /api/query-threads/{threadId}/fork-current
```

```typescript
POST /api/query-threads {
  scope: QueryScopeSpec
  originalQuestion: string
} -> QueryThread

WS /api/query | /api/query-files {
  reqId: string
  threadId: string
  question: string
  // 既有 current/file-set 上下文参数继续存在
}
```

- 前端不再把任意 `trace` 当持久真相提交;后端按 `threadId` 载入线程、校验范围与 freshness,再派生现有 `QueryTrace`。
- 首问必须与线程的 `originalQuestion` 一致;后续问题只在前一轮完整落盘后接受。
- 两条 WebSocket 都在 `done` 前把 `{question, answer, map, evidence}` 作为一个完整轮次写入同一线程。
- `done` 回传 `threadId` 与 `updatedAt`;前端据此更新列表摘要。陈旧、跨项目或范围不匹配在线路进入 LLM 前拒绝。
- 现有取源、Web Search、EvidenceCatalog、QueryMap 组装和 Prompt 模板保持原样;只改变轨迹来源与完成后的持久化副作用。

### 4. 阅读、继续与陈旧证据

- 选择历史线程只打开历史阅读,不得静默改变编辑器当前文件或已选文件集。
- fresh 线程若当前激活范围不同,显示“回到追问范围并继续”;用户点击后才打开对应当前文件或恢复文件选择集。
- stale 线程显示 `source-changed | source-missing` 原因,禁用输入框、续问按钮、代码 E# 与方向图代码证据跳转。
- stale 线程的 Markdown、方向图和网页来源仍可阅读;代码引用显示“旧源码证据,当前不可回切”。
- `source-changed` 的“基于当前源码新建追问”复制旧线程的原始问题与范围定义,由后端以当前内容生成新 ID/revision;不复制旧回答到新线程。`source-missing` 不提供该动作。
- 删除线程后,若它正被阅读则回到项目历史列表;若它正在流式请求则必须先取消请求再允许删除。

### 5. 单一追问状态与三态呈现

```typescript
type SidebarView = 'hidden' | 'explorer' | 'query'
type QueryPlacement = 'sidebar' | 'dock' | 'focus'
type QueryFocusReturn = 'sidebar' | 'dock'

interface QueryWorkspaceState {
  visible: boolean
  placement: QueryPlacement
  focusReturn: QueryFocusReturn
  selectedThreadId: string | null
  sidebarView: SidebarView
}
```

```text
Activity Explorer: QUERY/hidden -> EXPLORER; EXPLORER -> hidden
Activity Query:    EXPLORER/hidden -> SIDEBAR_QUERY; SIDEBAR_QUERY -> hidden
SIDEBAR_QUERY --移到底栏--> DOCK + EXPLORER
DOCK --移到左栏--> SIDEBAR_QUERY
SIDEBAR_QUERY|DOCK --专注--> FOCUS(returnTo=origin)
FOCUS --还原/Esc--> returnTo
任意呈现 --关闭--> hidden（线程选择和历史仍在 store）
```

- `QueryPanel` 只有一个逻辑实例;三种位置消费同一个 project-scoped controller/store。
- presentation 切换不得调用 `resetTrace()`、`teardown()` 或创建第二条 WebSocket。
- 左栏查询采用“历史列表 -> 线程详情”的窄栏两级导航;底栏/专注态用工具栏线程选择器,不同时堆两份历史列表。
- 资源管理器与追问器不会同时占左栏;活动栏始终保留。左栏重新打开时恢复上次 `sidebarWidth`。
- StatusBar 的“追问”继续作为显示/隐藏入口;ActivityBar 的“追问”明确切到左栏位置;工具栏提供左栏/底栏移动与专注按钮。
- 切项目根先取消旧项目在途请求,再换 `QueryThreadStore` 与历史列表;任何旧请求代次都不能写入新项目。

## S-QSTALE-1 · 陈旧线程只读与当前源码另建

- **状态**:已完成（2026-08-11）；前端按服务端 freshness 呈现源码一致/源码已变更/范围文件缺失，stale 阅读态统一关闭 composer、答案 E# 与方向图代码证据，`source-changed` 可显式另建 fresh 零轮次线程。
- **做**:显示 freshness 与 staleReason;fresh 线程在显式恢复其文件/文件集范围后可续问;stale 禁用输入与代码证据跳转,仅 source-changed 实现 fork-current 新线程。
- **不做**:不保存旧源码、不自动改写旧 revision、不把旧答案复制进新线程、不替用户静默切换当前编辑文件。
- **判据**:后端测试覆盖 current 与 selected 任一文件变化;前端检查覆盖 stale 文案、禁用 composer/E#、网页来源仍可开、恢复范围需显式动作、fork 新 ID/零 turns/新 revision;浏览器实测编辑一字节后旧线程立即只读且新线程可问。

## 端到端验收矩阵

| 场景 | 预期 |
| --- | --- |
| 新建两个同文件线程 | 左栏出现两条独立历史,第一问各自成为标题 |
| 关闭/重开追问器 | 当前线程、输入前的完整轮次与位置选择不丢 |
| 刷新浏览器/重启 Fluid | 完整历史恢复,同版本线程可继续 |
| 当前文件改变一个字节 | 旧线程只读,E# 不可回切,可基于当前源码另建 |
| 文件集只改变选择顺序 | revision 不变,线程仍 fresh |
| 文件集任一成员内容变化 | 线程 stale/source-changed,可基于当前源码另建 |
| 文件集任一成员缺失 | 线程 stale/source-missing,只读且不可 fork |
| 项目 A -> B -> A | B 看不到 A 历史;回 A 后历史仍在 |
| sidebar -> dock -> focus -> sidebar | 同一线程、同一请求、同一输入,无重挂丢失 |
| 流式失败或用户取消 | 部分回答可临时显示,但不作为完整 turn 续问 |
| 单条历史 JSON 损坏 | 其他历史可用,列表给出告警,坏文件不被静默删除 |
| 删除正在阅读的线程 | 显式确认后删除并返回列表;其他线程不受影响 |
