# 文件定向卡与证据化追问切片方案

> 状态:实施中（2026-08-05）;`S-GRAPH-1`、`S-ORI-1`、`S-ORI-2` 已完成,下一刀为 `S-ORI-3`。领域术语见 `CONTEXT.md`,关键权衡见 `docs/adr/0021-文件定向卡先行与源码证据化追问.md`。
> 本方案修订 ADR-0004/0006/0011/0017 的默认上下文路径,但不改变“文件是激活单元”“源码零字节污染”“跨文件取源不激活目标文件”三条铁律。

## 目标与边界

**做**:

- 每个激活代码文件先生成或命中一份文件定向卡,成功后才调度该文件的函数胶囊。
- 文件定向卡固定真实参与者、系统边界、类型归属、带方向的核心流、外围生产能力、具体贯穿示例、为什么需要以及源码证据锚点。
- 函数胶囊引用定向卡中的参与者 ID、流 ID 与阶段,不再独立发明“上游/下游”。
- 在项目根边界内发现 understand-anything 的全部项目/子项目作用域图谱;每个作用域优先现行 `.ua/knowledge-graph.json`,兼容旧 `.understand-anything/knowledge-graph.json`;图谱只导航,源码才是事实证据。
- 当前文件与已选文件集追问均能按问题取得有界的真实源码片段,不再只消费函数摘要。
- 追问器保留当前范围内的原始问题、后续问答和已纠正误解,切换文件/范围或新建轨迹时清空。
- 每次追问先展示结构化方向图,再解释核心链路、具体输入案例、为什么需要和外围能力;关键方向结论绑定源码证据。

**不做**:

- 不把追问器扩成跨文件长期保存的独立会话系统,不把聊天历史写入 `.fluid/`。
- 不把整仓库源码或所有依赖源码一次性塞入模型,不允许递归无限追源。
- 不因文件集追问而激活未打开文件;只能使用已有定向卡缓存或现有临时取源破例。
- 不把 knowledge graph 的 summary/edge 直接当成源码证据,也不让模型自行判定其回答是否正确。
- 不在本功能内建设通用 Rust/Python 数据流静态分析器或 LSP 服务器;AST/图谱只提供候选与边界。
- 不回写业务源码,不改变 Markdown 文档保持真空态的规则。

## 已确认的现状缺口

- `Capsule` 只有 `signature/summary/complexity/io`,没有参与者、方向、流阶段或证据字段。
- `build_gen_prompt` 每次只看目标函数源码与函数名称清单;前端当前固定发送 `shared: {}`。
- 当前文件追问请求只发送 roster、行范围和胶囊摘要,前端没有发送后端已经支持的 `focus`。
- 未超窗的小文件不会触发既有按需追源,因此文件级问题可能完全看不到源码。
- `GraphLoader` 只探测项目根的旧目录。实测同一工作区可同时存在根图谱与多个子项目图谱(如 `openinfer/.ua`、`openinfer/openinfer-kernels/.ua`、`openinfer/openinfer-qwen3/.ua`),且根图谱不保证收录子项目节点。
- 独立函数请求没有共享坐标系,已经出现把 `TokenEvent` 方向看反、把 `send_terminal_output` 误写成“发送给调度器”的事实错误。

## 已冻结契约

### 1. 文件定向卡

```typescript
type CodeEvidenceRef = {
  id: string                 // 卡内稳定 E1/E2/...
  filePath: string
  startLine: number          // 1-based,inclusive
  endLine: number            // 1-based,inclusive
  symbol?: string
}

type OrientationActor = {
  id: string                 // 卡内稳定 ID,如 vllm_frontend
  name: string               // 源码支持的真实名称
  role: string
  boundary: 'inside-file' | 'project' | 'external'
}

type OrientationType = {
  name: string
  ownerActorId: string
  meaning: string
}

type OrientationFlowStep = {
  fromActorId: string
  via: string                // 真实函数/通道/socket/调用
  payload: string            // 真实类型或控制信号
  toActorId: string
  why: string                // 缺少这一步会造成什么后果
  evidenceIds: string[]
}

type OrientationFlow = {
  id: string
  name: string
  kind: 'request' | 'response' | 'control' | 'stats' | 'other'
  why: string
  steps: OrientationFlowStep[]
}

type FunctionRole = {
  fnId: string
  lane: 'core' | 'supporting'
  flowIds: string[]
  stage: string
  receivesFromActorIds: string[]
  consumes: string[]
  sendsToActorIds: string[]
  produces: string[]
  why: string
  evidenceIds: string[]
}

type FileOrientationCard = {
  schemaVersion: number
  orientationId: string
  filePath: string
  purpose: string
  actors: OrientationActor[]
  types: OrientationType[]
  coreFlows: OrientationFlow[]
  supportingCapabilities: {
    name: string
    why: string
    functionIds: string[]
    evidenceIds: string[]
  }[]
  functionRoles: FunctionRole[]
  walkthrough: {
    title: string
    input: string
    steps: { text: string; evidenceIds: string[] }[]
  }
  invariants: { text: string; evidenceIds: string[] }[]
  evidence: CodeEvidenceRef[]
  coverage: {
    mode: 'full-source' | 'bounded-source'
    omittedFunctionIds: string[]
  }
}
```

确定性校验器必须在缓存/发送前拒绝:

- 重复 actor/flow/evidence ID,或任何悬空引用。
- 行号越界、路径不是当前激活文件、`startLine > endLine`。
- `functionRoles.fnId` 不在本次后端核验过的 roster 中。
- 核心流没有步骤、步骤没有证据、贯穿示例为空。
- 结构化字段出现无参与者坐标的“上游/下游”;卡内方向一律由 `fromActorId -> toActorId` 表达。
- `core`/`supporting` 角色重叠或函数无归属;允许辅助小函数归入 supporting,不允许完全失踪。

图谱提供的名称/关系只能影响候选选择。最终卡片中的每条核心 flow step 与 invariant 必须至少落到一个当前源码证据锚点。

### 2. 定向输入与大文件降级

```text
后端重读当前文件源码
  -> 校验前端 rosterSpans
  -> 从 GraphCatalog 解析当前文件最近祖先作用域的 GraphSnapshot(可空)
  -> 源码未超预算:带绝对行号的整文件进入定向生成
  -> 源码超预算:
       发送 imports/顶层类型/函数签名/行范围/图谱候选给规划调用
       规划调用只返回 {"need":["fnId", ...]}
       后端按已校验 span 精确切源并受总字符预算约束
       一轮生成 bounded-source 定向卡,不递归
```

- 规划模型只生成“需要哪些源码”的输入;真实源码与行号由后端确定性工具产出。
- 非法、重复、越界或不在 roster 的 ID 被忽略;剩余为空则返回可见错误,不伪造完整定向卡。
- `coverage.mode=bounded-source` 时必须列出未覆盖函数,追问不得把未覆盖实现说成已核验事实。
- 当前文件没有可归属的有效 graph 不阻断定向;它只减少候选提示,不改变源码读取路径。其他作用域的图谱不能冒充当前文件图谱。

### 3. 激活顺序与失败语义

```text
VACUUM
  -> LOADING
  -> PARSING
  -> ORIENTING(cache lookup / source planning / generation)
  -> ACTIVATING_CAPSULES
  -> ACTIVATED

ORIENTING --failure--> ORIENTATION_ERROR --retry--> ORIENTING
任意激活态 --switch/close--> VACUUM
```

- 定向卡命中或通过校验前,不得发出新的函数胶囊 LLM 请求。
- 定向失败时源码仍可读、错误可见且可重试;不得静默退回无坐标胶囊。
- 旧胶囊若没有匹配 `orientationId` 视为 miss,不得与新卡混用。
- 文件定向卡必须在首个函数胶囊之前可见;具体布局可迭代,协议不依赖布局。

### 4. 图谱目录、作用域归属与新鲜度

```text
discoverGraphs(projectRoot):
  scopeRoots = projectRoot itself and every descendant directory D for which either candidate exists:
    D/.ua/knowledge-graph.json
    D/.understand-anything/knowledge-graph.json
  for each D:
    choose first valid candidate in this scope only: .ua, then legacy
  return GraphCatalog(valid snapshots ordered deterministically)

resolveGraph(filePath, catalog):
  candidates = snapshots whose scopeRoot is an ancestor of filePath
  return candidate with the deepest scopeRoot, or None
```

`GraphSnapshot` 至少记录 `origin/scopeRoot/path/contentHash`,其中图谱节点的相对 `filePath` 必须相对 `scopeRoot` 解析并在规范化后仍落于该作用域。发现过程只在规范化后的 `projectRoot` 内进行,不跟随会逃逸边界的目录链接。

- `.ua` 优先是**每个作用域内部**的优先级,不是“根目录存在 `.ua` 就停止发现”。一个作用域的候选缺失或损坏不影响其他根/子项目作用域进入目录。
- 根图谱不被视为整个工作区的全集。单文件请求绑定最近祖先作用域;若子项目没有自己的有效图谱,才自然继承可覆盖它的最近上级图谱。
- 当前文件、临时跨文件目标和 selected 文件都先各自解析所属快照。跨作用域请求只合并各快照的相关切片,节点 ID 以 graph identity 隔离;没有源码或真实图谱边支持时不得合成跨图关系。
- 每次文件定向请求先做轻量目录与内容新鲜度探测。新增/删除更近作用域图谱会改变文件归属;图谱内容变化会改变相关切片;两者都必须使相关定向缓存 miss。

用于缓存身份的 `relevantGraphSetHash` 只覆盖本次实际使用的 `graph identity + 当前文件/相关符号节点和关系边`,按规范化 scope/path 排序后求 hash,避免无关作用域或无关文件变化冲掉全部卡片。

图谱摘要与边只作为:

- 定向规划的候选参与者/函数/跨文件目标。
- 追问相关源码的候选索引。
- 缺失信息的显式提示。

图谱不得直接成为 `CodeEvidenceRef`;任何关键结论必须回到后端读取的项目源码。

### 5. 缓存身份

```text
orientationKey = stableHash(
  fullFileSource,
  relevantGraphSetHash | "no-graph",
  providerBaseUrl,
  model,
  ORIENTATION_PROMPT_VERSION,
  ORIENTATION_SCHEMA_VERSION
)

orientationContextHash = stableHash(
  normalized actors/types/flows/functionRoles/evidence used by child prompts
)

capsuleKey = stableHash(
  functionSource,
  orientationContextHash,
  providerBaseUrl,
  model,
  CAPSULE_PROMPT_VERSION,
  CAPSULE_SCHEMA_VERSION
)
```

- 定向卡存入 `.fluid/orientations/<orientationKey>.json`;函数胶囊仍在 `.fluid/capsules/`。
- 文件、图谱归属或相关图谱切片变化先重算定向卡;若规范化坐标内容未变,兄弟函数胶囊仍可命中。
- 定向坐标变化时所有引用旧坐标的胶囊自然 miss。
- 定向、胶囊、选区、翻译分别使用产物专属 prompt/schema 版本,不再用一个全局 `p1` 误伤无关缓存。

### 6. 函数胶囊引用

`Capsule` 保留现有字段以便渐进迁移,新增:

```typescript
type Capsule = {
  fnId: string
  signature: string
  summary: string
  complexity: string
  io: string
  orientationId: string
  role: FunctionRole
}
```

- 胶囊 Prompt 注入经过校验的定向卡投影与该函数的 `FunctionRole`。
- `io` 不再接受“输入若干参数、输出 Result”作为充分解释;必须点名来源 actor、消费类型、去向 actor 与产物。
- 胶囊展示至少可见 `lane + stage + A -> B` 短链;详细 why/evidence 可展开。
- 行级注释继续解释局部动作,但遇到通道、请求、事件、输出时必须沿同一 actor/flow ID 命名。

### 7. 有界追问轨迹

```typescript
type QueryTurn = {
  question: string
  answer: string
  codeEvidenceIds: string[]
}

type QueryTrace = {
  scopeKey: string              // current:<path> 或 selected:<sorted paths>
  scopeRevision: string         // 当前 orientationId/文件集源码身份
  originalQuestion: string      // 轨迹内恒保留
  turns: QueryTurn[]
}
```

- 前端持有轨迹并随每次追问发送;后端不按 `traceId` 暗存会话,请求仍可重放。
- 预算不足时恒保留 `originalQuestion` 与最近若干完整 turn,从最旧中间 turn 开始裁剪并插入显式省略标记。
- 前序回答只是“已进行过的解释与纠正”,不是代码证据;当前源码与证据锚点冲突时必须纠正历史。
- 切换文件、切换 current/selected scope、源码身份变化或用户点击“新追问”即清空。
- 轨迹不写 `.fluid/`、不跨项目、不进入联网检索词。

### 8. 相关源码与证据装配

```text
assembleQueryEvidence(question, trace, orientation, scope):
  read current source(s) from ProjectReader
  resolve each source file against GraphCatalog; keep graph identities isolated
  include source for explicit focus/selection when present
  if active file fits QUERY_INLINE_SOURCE_BUDGET:
      include full numbered source
  else:
      plan need[] over orientation + rosterSpans + question + trace
      validate IDs and slice exact source once
  add source spans behind relevant orientation core steps
  add cross-file/selected-file spans through existing bounded ephemeral fetch
  dedupe spans and enforce one shared budget
  emit EvidenceCatalog(E1..En)
```

- “相关”由当前问题、原始问题、最近追问、显式 focus 和定向卡核心流共同决定,不再等到“摘要超窗”才允许追源。
- 小/中型活动文件优先直接提供整份真实源码,避免摘要先验污染。
- 大文件与多文件只允许一轮 source planner;planner 只能返回可验证的函数/图谱节点 ID。
- 多文件跨越图谱作用域时,planner 输入与返回 ID 都带 graph identity;后端分别在各自 `scopeRoot` 下解析路径,不得把某份图谱的相对路径套到项目根或另一作用域。
- 后端为每段源码分配 `E1..En`,最终 Prompt 只允许引用目录中存在的 ID。
- 网页来源继续走 `EvidenceStatus/SourceLink`;代码证据与网页引用分开呈现。

### 9. 追问方向图与回答契约

新增先于任何 `delta` 的结构化帧:

```typescript
type QueryMap = {
  actors: OrientationActor[]
  direction: OrientationFlowStep[]
  coreFunctionIds: string[]
  supportingFunctionIds: string[]
  walkthrough: FileOrientationCard['walkthrough']
  evidence: CodeEvidenceRef[]
}

type QueryFrame =
  | { kind: 'map'; map: QueryMap }
  | ExistingQueryFrame
```

可见顺序固定为:

```text
1. 方向图:具名 actor --真实 payload/via--> 具名 actor
2. 核心链路:先解释完成主要职责不可缺的步骤
3. 具体输入:用一个 request/input 从入口走到最终输出
4. 为什么需要:说明批量、状态、桥接、校验等设计动机与缺失后果
5. 外围生产能力:统计、tracing、缓存、LoRA、utility、清理等单列
6. 代码证据:关键结论引用 [E1] 形式的源码锚点
```

- `map` 必须先发送并先渲染,从协议上保证方向先于长篇解释,不依赖模型是否听从 Markdown 排版要求。
- 没有跨组件数据流的局部问题仍返回最小 map,明确“无跨组件流”,并给出直接作用与证据。
- 最终回答 Prompt 同时获得原始问题、当前问题、裁剪后的追问轨迹、QueryMap、EvidenceCatalog 和真实源码片段。
- 关键方向/调用链段落必须使用已知 `[E#]`;未知 ID 不生成链接并显示可见警告。
- 模型可以做解释和组织,但不能创建 actor ID、flow ID、函数 ID、证据 ID 或源码行号。

### 10. 接口增量

```typescript
WS /api/orient
  client -> { reqId, filePath, rosterSpans }
  server -> { kind:'cache-hit' }
          | { kind:'status', phase:'planning-source'|'orienting', message }
          | { kind:'card', card:FileOrientationCard }
          | { kind:'done' }
          | { kind:'error', message }

WS /api/generate
  client -> ExistingGenerateRequest & { orientationId:string }

WS /api/query
  client -> ExistingQueryRequest & {
    orientationId:string
    trace:QueryTrace
  }
  server -> status* -> map -> evidence? -> delta* -> done | error

WS /api/query-files
  client -> ExistingQueryFilesRequest & { trace:QueryTrace }
  server -> status* -> map -> evidence? -> delta* -> done | error
```

- 后端根据 `orientationId` 读取自己生成的卡片并核对当前源码身份;不信任前端回传完整卡片。
- selected scope 只复用已有定向缓存;没有缓存的未激活文件仍走图谱候选 + 有界临时取源,不得后台偷偷生成卡片。
- 既有 `GET /api/project/graph -> KnowledgeGraph | null` 在 v1 保留为**项目根作用域兼容视图**;不得把目录内多图合并后塞回旧响应。`GraphCatalog` 只作为服务端内部依赖;未来若需向 UI 暴露目录,另增有 graph identity/scopeRoot 的接口。

## S-GRAPH-1 · 多作用域图谱发现、归属与新鲜度

- **做**:把 GraphLoader 从根目录单例改为 `GraphCatalog`;在项目根边界内发现全部根/嵌套子项目图谱,每个作用域独立执行 `.ua` 优先、旧路径回退;引入 `GraphSnapshot(origin,scopeRoot,path,contentHash)`、最近祖先归属和 relevant graph-set hash;定向请求前可检测目录及内容变化;旧 `GET /api/project/graph` 只投影根作用域以保持响应结构兼容。
- **不做**:不生成定向卡,不改函数胶囊/追问 Prompt,不做 UI,不把不同作用域节点/边合并成一份 `KnowledgeGraph`。
- **判据**:临时目录测试覆盖仅根图谱、仅嵌套图谱、根+子项目、两个兄弟子项目、同作用域新旧并存/首选损坏回退、某作用域损坏不屏蔽其他作用域、最近祖先胜出、无局部图时继承上级、节点相对路径按 scopeRoot 解析、目录链接逃逸拒绝、新增/删除更近图谱改变归属、内容变化 hash 改变、都缺失返回 `None`;路由测试断言旧 endpoint 只返回根作用域且从不盲合并子图;Rust tests 与严格 clippy 绿。
- **触达**:`graph_loader.rs`;`routes.rs:ProjectCtx/open_folder/graph` 的目录持有与兼容投影;`main.rs` 的多图启动摘要;`context_assembler.rs` 的图谱切片辅助及对应测试。
- **落盘产物**:所有消费者共享的可刷新多作用域图谱目录,不再把根图谱误当全集,也不把图谱目录名硬编码到业务路径。

## S-ORI-1 · 文件定向类型、确定性校验与旁路缓存

- **做**:落 `FileOrientationCard`/`CodeEvidenceRef` 等 Rust 类型、规范化 hash、校验器与 `.fluid/orientations/` 缓存。
- **不做**:不调用 LLM,不加路由,不改前端,不改变胶囊缓存。

## S-ACC-1 · `bridge.rs` 黄金验收与文档收口

- **做**:加入最小化 `bridge.rs` 测试夹具、期望定向契约与 current-query 端到端 fixture;完成真实浏览器路径;更新技术方案、代码链路、README 与 checkpoint。

## 全程验证纪律

- LLM 负责提出 card/source-plan/解释候选;Rust/TypeScript 校验器、缓存键、测试 runner 和真实源码切片负责判定协议与证据是否成立。
- 每个模型产物都先过结构校验再缓存;错误结果不污染旁路缓存。
- 任何“关键结论有证据”的验收都必须能从 E# 确定性回切当前源码,不能用另一次模型评分代替。
- 真实供应商 smoke 只回答“该配置能否产出通过 schema 的结果”,不证明语义必然正确;`bridge.rs` 结构事实由固定夹具断言。
- 每刀开始前按 A1 重新声明做/不做/判据;每刀完成即更新代码链路,结构变化同步技术方案。
